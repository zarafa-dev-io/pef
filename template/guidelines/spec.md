# Consignes de contenu — Specifications

> Exemple de consignes par type (optionnel) : dupliquez ce modèle pour d'autres suffixes (`us.md`, `bug.md`, `doc.md`…) selon vos besoins. Propriété du projet.

- Le **Comportement** se lit comme un déroulé observable : chaque étape numérotée décrit ce que voit ou obtient l'utilisateur, jamais l'implémentation.
- Tout cas d'erreur identifié a son message dans la section **Messages d'erreur** — un comportement d'erreur sans message est une spec incomplète.
- Les bornes et formats des champs sont explicites (longueurs, casse, caractères admis) : c'est là que naissent les cas limites des AC.
